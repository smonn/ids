## Open findings (ranked)

1. **Medium (security) — GraphQL `verifyIdArgs` unknown-key guard caches per wrapper, not per field.** `src/adapters/graphql.ts:114-131`. `argNamesChecked` is a single closure boolean, so a wrapped resolver mounted on two schema fields validates codec-map keys only against whichever field is invoked first — a key that is a typo relative to the second field silently no-ops verification there, exactly the fail-open the guard shipped to close, and which field wins is request-order-dependent. Companions, same files: the `field === undefined` fallthrough skips the guard while the JSDoc claims "fail-closed" (per-ID verification still runs; the _guard_ is what's skipped — qualify the claim), and two `graphql.test.ts` fixture sites still hand-roll the signed/wrapped codec construction that `makeRealSignedCodec`/`makeRealWrappedCodec` centralized. **Direction:** key the check on `${info.parentType.name}.${info.fieldName}` (small `Set`); qualify the JSDoc; migrate the two fixture stragglers. Found independently by four reviewers. **Disposition: file (ready-agent).**

2. **Medium (security/correctness) — Prisma single-object `createMany` bypasses the new present-value validation and generation.** `src/adapters/prisma.ts:204-209`. Prisma accepts `createMany({ data: {…} })` (non-array `Enumerable<T>`); the `Array.isArray(data)` guard passes it through with neither injection nor validation, so a cast-smuggled invalid ID is stored via exactly the path the fix claims to close — and `website/.../prisma.md` now asserts the logic applies "to each element". Same-file companions: `injectIfAbsent` no longer describes its behavior (it validates present values since this wave — a reader "simplifying" the present branch back to passthrough reintroduces the bug); upsert's present-valid pass-through is untested. **Direction:** handle the non-array shape (`data != null && !Array.isArray(data)` → inject/validate), rename the helper (e.g. `injectOrValidate`), add single-object-form and upsert-pass-through tests, align `prisma.md`. **Out of scope:** validating upsert's `update` arm — the update path is documented caller-owned (the `:::note[update / updateMany limitation]` shipped this wave records that disposition). **Disposition: file (ready-agent).**

3. **Medium (security) — CLI echo hygiene: the redaction sweep missed the flag-value and env echo sites.** `src/cli/args.ts:60,92`, `src/cli/flags.ts:9,24`, `src/cli/verbs.ts:341,351`, `src/cli/key.ts:23,29,58,61`. The fix routed positionals, unknown command/verb, and batch-stdin tokens through `redactToken`, but `unsupported flag:`/`flag does not take a value:` echo arbitrary `-`-prefixed argv verbatim (ESC/BEL intact), and the `--count`/`--kind`/`--value`/`--key-encoding`/`IDS_KEY_ENCODING` failure branches echo raw values precisely when they fail their whitelist checks — terminal escape injection and full-length secret leak for a key pasted into the wrong flag, the exact class the sweep closed. (Range-error echoes of regex-passed digit strings are safe.) Same-area companions: `redactToken` strips C0/DEL/C1 but not Unicode bidi/format controls (U+202E can visually reorder the error line) and its `slice(0,20)` can split a surrogate pair; the new key-file permission boundary tests cover group/other read+write bits but not the exec bits (a mask revert from `0o077` to `0o066` passes the suite); the strip regex could hoist to module scope. **Direction:** route the failure-branch echoes through `redactToken` (or a strip-only variant where truncating a path is unwanted), extend the strip class with `U+200B-U+200F U+202A-U+202E U+2066-U+2069`, truncate on code points, add `0o610`/`0o601` boundary tests, note the truncate-and-strip behavior in `cli.md`. **Disposition: file (ready-agent).**

4. **Medium (test) — the verify-plumbing refactor's seams are under-pinned.** `src/adapters/adapter-types.ts:105-110` and the four HTTP adapter test suites. `resolveVerifyFailure` has no unit test and its `status.malformed` override is pinned only in `nestjs.test.ts` — a call-site regression to `resolveVerifyFailure()` in express/fastify/hono passes the suite; fastify's verify-path `onError`/fallback branch has zero coverage (express and hono both cover theirs); the fail-closed runtime assertion in fastify/hono is only `not.toBe(200)`; the `@ts-expect-error` verify type-locks cover `idParam` but not `idQuery`. **Direction:** unit tests for `resolveVerifyFailure` (default + override), one verify-path status-override test per adapter, fastify verify+log-only-hook and verify+replying-hook tests, strengthen the weak assertions, one `idQuery` type-lock per adapter. **Disposition: file (ready-agent).**

5. **Medium (architecture) — depcruise follow-throughs the fix wave opened or left.** `.dependency-cruiser.cjs`, `.dependency-cruiser-fixtures.cjs`, `src/depcruise-rules.test.ts`, `test/fixtures/depcruise/`. (a) Exempting `src/adapters/test-helpers.ts` from `adapters-no-internals` (needed for the real-codec fixtures) left that file with an ungoverned import surface — the same commit whose purpose was closing ungoverned edges; give it its own allowlist rule (types/error, adapter-types, codec public entrypoints). (b) The derived fixtures config silently drops rules whose `from` uses keys other than `path`/`pathNot`, silently ignores stale `FROM_OVERRIDES` keys, and nothing asserts every main-config rule name appears in the test's `cases` — a rule added tomorrow ships untested with green CI; add a sync test. (c) Each upward-edge fixture probes one forbidden target only (adapters), so loosening an allowlist toward `src/cli/` passes all 35 tests; add one cli-target fixture per allowlist rule. (d) `layouts-no-shell` is now fully subsumed by `layouts-wire-imports-allowlist` — the exact redundancy the wave removed for codec constructors; remove it citing that same rationale. (e) The `codec-constructors-imports-allowlist` comment says "their own layout and key" but the regex permits any codec's; note the `codec-slice-no-cross-codec-imports` backstop. **Disposition: file (ready-agent).**
