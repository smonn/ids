## Open findings (ranked)

1. **High (maintainability/security-process) — `src/cli/sanitize.ts` ships as a git-binary blob.** The `STRIP_RE` character class embeds a literal raw NUL byte plus raw bidi/format code points (the Trojan-Source class, CVE-2021-42574 family) instead of `\uXXXX` escapes, so git classifies the file as binary: `git diff`/GitHub PR view render "Binary files differ", `git blame`/`log -p -S` are useless, and `grep -r` over `src/` reports "binary file matches" without content — the one file whose job is stripping hostile characters before echo is structurally unreviewable and invisible to every future text-based audit or codemod. Found independently by five reviewers. Verified: the bytes decode to exactly the intended class `[\u0000-\u001F\u007F\u0080-\u009F\u200B-\u200F\u202A-\u202E\u2060-\u2069\uFEFF]` — no functional bug. Companions, same file: U+2028/U+2029 (Zl/Zp line/paragraph separators) render as real newlines in many terminals/log viewers and are not in the class — a spoofed extra stderr line remains possible; `redactToken("")`/`stripToken("")` are unpinned; the sanitizers have no direct unit-test file. **Direction:** rewrite the class with escapes; add U+2028–U+2029; add `src/cli/sanitize.test.ts` (ranges, empty string, surrogate boundary); add a repo-hygiene test rejecting raw NUL/bidi/format bytes in tracked source so the class can't recur. **Disposition: file (ready-agent).**

2. **Medium (security) — CLI echo hygiene: the #971 sweep left two verbatim sites, two under-redacted sites, and zero call-site tests.** (a) `src/cli/verbs.ts:75` echoes `--at`'s raw value on the invalid-date branch — the only arbitrary-string flag echo left unredacted (the digit-gated echoes in flags.ts/verbs.ts are safe); (b) `src/cli/key.ts:71-73` interpolates the `--key-file` path twice into the group/other-permission warning with no strip — two lines below the sites #971 wrapped; (c) `src/cli/key.ts:24,30` route `--key-encoding`/`IDS_KEY_ENCODING` failures through `stripToken` (full-length) — these are enum flags, not paths, so the truncation carve-out doesn't apply and a key pasted into the wrong flag still leaks full-length to stderr/CI logs (this was the audit's motivating scenario; the shipped `cli.md` note also overstates that flag values are truncated); (d) not one of #971's new `redactToken`/`stripToken` call sites has a test feeding hostile bytes end-to-end — reverting any single wrap passes the full suite. Same-file companion: `router.ts` imports `redactToken` through `verbs.ts`'s forwarding re-export instead of `./sanitize.js` directly. **Direction:** redact (a) and (c), strip (b); class-level test AC — one control/bidi-bearing input per echo site across args/flags/key/verbs tests asserting the emitted message excludes the raw bytes; align `cli.md`; drop the forwarding re-export. **Disposition: file (ready-agent).**

3. **Medium (security/correctness) — Prisma `defaultQuery` never wraps `createManyAndReturn`.** `src/adapters/prisma.ts:197-233` defines hooks for `create`/`createMany`/`upsert` only; `createManyAndReturn` (a distinct client-extension operation, present in the pinned `@prisma/client` 7.x) falls through with neither injection nor validation — a caller-supplied invalid ID is stored via an automatic insert path, the exact class #945/#966 closed for the other three ops. Not covered by the update-path caller-owned carve-out (this is an insert). Companion: ID fields nested in relation writes (`data: { posts: { create: {...} } }`, `connectOrCreate.create`) are also unreached by the hooks — a real gap, but one to document as a limitation (parallel to the shipped update/updateMany note), not to chase through Prisma's nested-write tree. `updateManyAndReturn` is update-path → caller-owned, no action. **Direction:** add a `createManyAndReturn` handler mirroring `createMany`'s array/single-object branches + tests; document the nested-write limitation in `prisma.ts` JSDoc and `prisma.md`. **Disposition: file (ready-agent).**

4. **Medium (duplication) — the #974 helper sweep left the `.cause`-asserting variant unswept.** ~24 sites across `drizzle/kysely/typeorm/mikro-orm/prisma.test.ts` still hand-roll try/catch + `isIdsError` + `.code` + `.cause` boilerplate that `expectInvalidIdError` almost covers — well past the ADR-0014 warrant, in files the same commit touched. **Direction:** extend the helper (e.g. optional `{ cause }` matcher) and migrate; if `test-helpers.ts` outgrows one concern, split assertion helpers from spy factories. **Disposition: file (ready-agent, chained after finding 3 — prisma.test.ts overlap).**

5. **Medium (maintainability/CI) — the changeset-check Conventional-Commits pattern is a hand-narrowed copy synced only by a comment.** `changeset-check.yml:60` re-states the type/scope regex from `pr-title.yml:30` with a narrowed type set (`feat|fix|perf`); "Keep this pattern in sync" is the only enforcement. A type added or scope-charset change in one file silently desyncs the gate. **Direction:** a `.github/scripts` sync test that parses both workflow files and asserts the changeset-check type set is a subset of pr-title's and the scope fragments are byte-identical (script-level test avoids the workflows-permission boundary). **Disposition: file (ready-agent).**

6. **Low (architecture) — depcruise follow-throughs.** (a) The fixture-sync assertions cover path-scoped rules only; a future non-path-`from` rule (e.g. `orphan`) ships untested with green CI — extend the sync test with an explicit structural-rule skip-list; (b) `FROM_OVERRIDES` *values* are unvalidated — a fixture-directory rename silently desyncs; assert each override path matches an existing fixture; (c) the `no-shell-layout`/`no-shell-layout-router` fixture files orphaned by the `layouts-no-shell` removal are still in the tree — delete. **Disposition: file (ready-agent).**

7. **Low (test) — adapter test tightening.** `fastify.test.ts:811,1153` / `hono.test.ts:478,602` stop at `toBeGreaterThanOrEqual(400)` where exact-status pinning was directed (a 400→500 regression passes); `graphql.test.ts:491` covers the per-coordinate guard in one call order only — add the reversed order with a typo'd codec-map key on the second field. **Disposition: file (ready-agent).**

8. **Low (CI) — fork PRs skip the docs-coverage gate entirely.** `docs-coverage.yml:38`'s job-level fork guard (needed only for the comment step's write perms) means an external contributor's PR satisfies branch protection with the gate "skipped" — the one gate left porous for the least-trusted population, while changeset-check and ci still run on forks. **Direction:** run mapping+fail read-only on forks and skip only the comment step, or record fork-PR docs review as human-only in CONTRIBUTING. Workflow-file change → maintainer session. **Disposition: file (ready-human).**

9. **Low (docs) — doc roundup.** `CONTRIBUTING.md:56` cites superseded ADR-0008 for the depcruise rules (→ ADR-0018); the `verifyIdArgs` coordinate is written `parentType.fieldName` in CONTEXT.md and `graphql.md` but built as `parentType.name + "." + fieldName` (JSDoc says `parentType.name.fieldName`) — align the three; add the note that changeset/docs waivers are PR-body text, not labels (a `changeset:none` label does not satisfy the live gate). **Disposition: file (ready-agent).**
