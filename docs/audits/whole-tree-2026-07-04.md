# Audit — whole source tree (2026-07-04, post-security-audit pass)

Point-in-time snapshot. **Non-authoritative**: superseded by whatever issues are filed from it; per convention it carries no issue numbers. Performed at commit `ae12379`. This pass runs the same evening as the full-codebase security audit (`security-audit-2026-07-04.md`, taken at `4099780`); the 15 commits between the two snapshots shipped every finding filed from that audit (#908–#924), so the issue backlog was empty at audit start and the new verify/validation surface from those commits was weighted as the least-audited code.

**Scope:** whole `src/` tree, plus `bin/`, `test/`, `spec/`, `bench/`, `docs/adr/`, `website/`, and the depcruise configs. **Method:** ten parallel dimension reviewers (security-core, security-input-surface, correctness, performance, duplication, accidental complexity, test quality, maintainability, architecture, documentation), each gated against the decided digest (all 37 ADRs — Accepted by default, ADR-0008 superseded by 0018, ADR-0015 Rejected, ADR-0028 superseded by 0033 — plus the SPEC/CONTEXT/CONTRIBUTING closed items and the dispositions recorded by the four prior audit snapshots). Contested findings were grilled against the ADRs and verified in code before disposition.

The trust-critical core is again clean: **no Critical or High findings anywhere**. The kernel, codec constructions, wire layer, and CLI key handling all re-verified sound (HKDF label separation, sign-only key usages post-#908, constant-time comparisons everywhere including the CLI, CSPRNG discipline, MAC widths per ADRs, no secret leakage into errors). The open findings cluster in the newest code — the #917/#923/#924 verify surface and the #911 write-validation sweep — plus doc/ADR drift those PRs left behind.

## Open findings (ranked)

1. **Medium (security) — NestJS pipe fails open when a non-throwing `onError` hook is set.** `src/adapters/nestjs.ts:103,124`. `transform` does `return this.options.onError(failure)`; a log-only hook (JS consumer, or the `as never` cast that `nestjs.test.ts:132` pins) makes the pipe resolve `undefined`, and the route handler runs with `undefined` typed as `Id<Brand>` — including on the #917 verify branch, i.e. after a forged HMAC tag. Express/Fastify got runtime fallbacks in #912; NestJS relies only on the compile-time `=> never` annotation. Found independently by two reviewers. **Direction:** after the hook returns without throwing, throw the default exception anyway (mirror `express.ts:146-148`); update the pinning test. **Disposition: file (ready-agent).**

2. **Medium (security/correctness) — Prisma write-path gaps.** `src/adapters/prisma.ts`. (a) `defaultQuery`'s `injectIfAbsent` only fills absent fields; caller-supplied `data[fieldName]` values pass through unvalidated, so #911's stated threat (cast-smuggled string rejected at the write site) is unmet on Prisma's automatic path — garbage is stored, then poisons every later read. (b) `nullableIdField().write` delegates to the non-nullable `writeIdColumn` and is typed `(value: Id<Brand>) => string`, contradicting ADR-0034's nullable axis ("null passthrough"); every sibling adapter's nullable write uses `writeIdColumnNullable`. (c) `prisma.ts:62-66` JSDoc still says the write path is "an identity function at runtime". **Direction:** validate present values in the three `defaultQuery` hooks (throw `IdsError("invalid_id")`); switch (b) to `writeIdColumnNullable` with a widened signature; refresh the JSDoc; add per-adapter write-rejection tests; document that Prisma `update`-path IDs remain caller-owned. **Disposition: file (ready-agent).**

3. **Medium (test) — #911's write-path rejection is untested at every ORM adapter seam.** `src/adapters/{drizzle,kysely,typeorm,mikro-orm}.test.ts`. Rejection is tested only on the shared helpers; every per-adapter write test is happy-path, so reverting any single adapter's `toDriver`/`to`/`convertToDatabaseValue` to identity would pass the full suite. `mikro-orm.test.ts:28` title still reads "identity pass-through" — stale and now false. **Direction:** one smuggled-invalid write-rejection test per adapter; fix the title. (Prisma's test lands with finding 2 — same-file rule.) **Disposition: file (ready-agent).**

4. **Medium (duplication/maintainability) — #917/#924 verify plumbing copy-pasted across the four HTTP adapters.** The `options?.verify → safeVerify(raw) → {reason:"malformed", status: options.status?.malformed ?? 400}` sequence is repeated at 7 sites with an inline magic 400 (the default otherwise lives solely in `resolveIdParamFailure`), and the #912 hook-fallthrough dance is repeated 4× inside each of express/fastify/hono. A future change to either contract must land in 7–16 places or adapters silently diverge — the worst failure mode, since sibling tests keep passing. Grilled against ADR-0036: the ADR chose the codec-side alias so the eight blocks _could stay_ byte-identical; it does not prohibit extracting the shared block, and byte-identity is what makes extraction trivially safe. **Direction:** shared `resolveVerifyFailure` beside `resolveIdParamFailure` in `adapter-types.ts` (framework-native _emission_ stays per-adapter, preserving ADR-0020); per-file `emitFailure`/`storeLocal` locals in express/fastify/hono; while touching these blocks: fix the 8 stale "Signed-only" JSDoc sites left by #924, hoist express's per-request `Object.defineProperty` descriptor (keep defineProperty semantics — it is deliberate proto-safety), and widen `verify?: true` to `verify?: boolean` so computed flags compile. **Out of scope:** retyping `IdVerifiableCodec.error` (ADR-0036 records it as deliberately-loose `unknown`) and removing the safeParse+safeVerify double parse (accepted; negligible next to the HMAC). **Disposition: file (ready-agent, chained after finding 1 — shared file).**

5. **Medium (docs) — GraphQL surfaces missed by #924's doc sweep.** `src/adapters/graphql.ts:76` JSDoc + `website/.../adapters/graphql.md:79` still claim "Only the Signed Timestamp codec satisfies IdVerifiableCodec; passing any other codec is a compile-time type error" — false since #924; contradicts `adapter-types.ts:14`, CONTEXT.md, and `wrapped.md`. Found by five reviewers. Related same-file items: `verifyIdArgs` recomputes `Object.keys(codecs)` per resolver invocation (hoist the entries array out of the factory); a typo'd codec map key silently disables verification (add a lazy first-invocation guard against the field's declared args, fail-closed); no test exercises `verifyIdArgs` with the Wrapped key codec. **Disposition: file (ready-agent).**

6. **Medium (architecture) — codec-slice upward edges unenforced in depcruise.** `.dependency-cruiser.cjs`: codec `index.ts`/`key.ts` rules constrain `to` within `^src/wire`/`^src/codecs` only, so a codec importing `src/adapters/*`, `src/cli/*`, or `src/index.ts` fires nothing (only `layout.ts` has a full `^src` allowlist); the ring is enforced one-directionally. Companions: the fixture config drifted from main on 3 rules' `to` side (the negative-fixture harness now tests stale rule copies), and `wire-no-shell`/`layouts-no-shell` still name only `cli/index.ts` from back when the CLI was one file. **Direction:** `^src`-wide allowlists for codec index/key; derive the fixture config from main programmatically (remap `from` only); broaden the no-shell `to` to `^src/cli/`. **Disposition: file (ready-agent).**

7. **Medium (docs) — #923 shipped a new public export with no changeset.** v1.2.0's CHANGELOG omits `verifyIdArgs` entirely; the 7 changesets consumed by `ae12379` cover every other behavior PR. **Direction:** retroactive CHANGELOG entry under 1.2.0. **Disposition: file (ready-agent, doc roundup).**

8. **Low (security) — CLI hygiene leftovers from #913.** `src/cli/commands/convert.ts:20` and `src/cli/router.ts:62,80` echo argv tokens verbatim (a misplaced secret reaches stderr unredacted; `verbs.ts` redacts the same case); batch-inspect stderr (`verbs.ts:281`) echoes raw stdin lines with no control-char stripping (ANSI/C0 injection into the operator's terminal). Same-file companion: `InspectSpec` doesn't tie `keyed: true` to key presence, forcing three `!` assertions — make it a discriminated union. **Disposition: file (ready-agent).**

9. **Low (security/test) — key-file permission mask covers read bits only and its boundaries are untested.** `src/cli/key.ts:69` (`0o044`): group/other-_writable_ key files (0o622) pass silently; tests cover only 0o644/0o600. **Direction:** widen the mask to any group/other bit (`0o077`); add single-bit boundary tests. **Disposition: file (ready-agent).**

10. **Low (test) — HTTP verify test gaps.** 4/5 adapters lack the `@ts-expect-error` lock and any runtime test for `verify: true` with a non-verifiable codec (only graphql has the lock); `express.test.ts` settles async verify middleware with 6× fixed `setTimeout(50)` sleeps (flake risk); the real wrapped/signed codec fixtures are copy-pasted ~29× across the four suites instead of living beside the spy factories in `test-helpers.ts`. **Disposition: file (ready-agent, chained after finding 1 — nestjs.test.ts overlap).**

11. **Low (docs) — ADR corrections.** ADR-0018's ring diagram and responsibilities table omit `mikro-orm.ts` (the correction blockquote lists all five), and its add-a-codec step list misses `src/cli/help.ts`'s hardcoded verb→codec usage text (a 7th codec added per the ADR ships with wrong `--help`); ADR-0033 cites `src/cli/variants.ts`, dissolved by the ADR-0032 implementation. Dated correction notes per ADR-FORMAT. **Disposition: file (ready-agent).**

12. **Low (docs) — one-line drift roundup.** SECURITY.md supported-versions table still says 1.0.x at v1.2.0; CONTEXT.md's IdCodec entry still claims adapters validate "on the read path" only and "never call key-dependent methods" (stale on both counts after #911/#917); `_kernel/crypto.ts:7` `timingSafeEqual` precondition comment predates the 32-byte digest callers; `cli/output.ts:5` uses the banned term "signed codec"; drizzle/kysely/mikro-orm/typeorm write-path docstrings still say "identity"/"passes through unchanged" (deny an `IdsError` the caller can now hit). **Disposition: file (ready-agent, batched — all one-liners, disjoint from the code issues).**

13. **Low (correctness) — no conformance vector pins the `i`/`l` → `1` alias.** `spec/vectors.json` pins only `o → 0` (line 195) while SPEC.md:106 claims the canonicalize vectors pin the lenient→canonical mapping; a port mishandling i/l aliasing passes the committed oracle. Append-only case addition per ADR-0026. **Disposition: file (ready-agent).**

14. **Low (performance) — new hot paths lack named benches.** `bench/index.ts` covers `writeIdColumn` and single-key `safeVerify` success (the exact #917 per-request op) only by proxy, so a regression in adapter glue is invisible to the CI bench comparison. **Disposition: file (low-priority).**

## Dropped (with reason)

- **Retype `IdVerifiableCodec.error` to `ParseError | "verification_failed"` / single-`safeVerify`-call redesign** (complexity Medium) — DROP: ADR-0036 explicitly records the `error: unknown` looseness as deliberate and the canonical-id-from-`safeParse` flow as the design; the double parse is measured noise next to the HMAC. The mechanical dedup half of the finding survives as open finding 4.
- **`verifyIdArgs` should substitute canonical IDs into `args`** (security-core Low) — DROP, closed:ADR-0035: "All pass → the original resolver is invoked with `args` unchanged" is the recorded contract; the idScalar pairing is the documented canonicalization path.
- **Revert express `res.locals` writes to plain assignment for speed** (performance Low) — DROP as stated: `Object.defineProperty` is deliberate proto-safety from #917; only the descriptor hoist survives, folded into finding 4.
- **NestJS failure→exception mapping duplicated 2×** — DROP: at, not over, the ADR-0014 warrant; folds free if finding 4 lands.
- **Kysely `idPlugin` dot-qualified throw is plain `Error`** — closed:ADR-0011 (construction-time programmer misuse carve-out; documented in JSDoc, deliberate #910 shape).
- **Architecture's counter-claim that the 8× verify blocks are settled by ADR-0036** — overridden after reading the ADR: it constrains codec-vs-adapter placement and the interface, not intra-adapter extraction (see finding 4's grill note).

## Verified sound

- **Crypto kernel and codecs:** five HKDF labels distinct, base and derived keys non-extractable, #908 sign-only usages hold (verification is recompute-then-`timingSafeEqual` everywhere; zero `subtle.verify`/`exportKey` in src); every secret-derived comparison constant-time including CLI `digest match`; CSPRNG discipline intact (`fastTenByteRng` harvests only the 122 random UUIDv4 bits); MAC messages fixed-width/length-prefixed with brand (and kind/ns) bound — no splice ambiguity, no cross-brand transplant.
- **Wire (#916):** classification matches SPEC's rejection layers on all probed edges (empty, non-string, U+212A in brand vs payload, overlong × right/wrong prefix); alias resolution payload-only, after ASCII-only fold, before the `[048cgmrw]` final-char check; round-trips verified on all-zero/all-0xFF/2⁴⁸−1 payloads against the committed vectors; no >32-bit shift arithmetic outside bigint lanes.
- **Verify surface (#917/#923/#924):** structural parse precedes every MAC; verified value ≡ stored canonical `result.id`; no adapter lets the handler run on failure (express `.then/.catch` + headersSent, fastify/hono awaits, Nest promise) — the NestJS hook path (finding 1) is the one exception; `verify: true` with a non-verifiable codec fails closed at runtime in all four; tag failures map to generic `malformed` without echoing input; tamper coverage at the adapter level is real (bit-flip forgeries with structural-validity controls, both codecs).
- **Write path (#911):** exactly one `safeParse` per insert on the canonical fast path; drizzle/kysely/mikro-orm/typeorm wired through the shared helpers correctly (Prisma: finding 2); generating variants inject only when absent.
- **Layering:** depcruise clean at HEAD (148 modules, 0 violations); adapters import only hub/types/error; ADR-0034/0035/0036 match shipped code exactly; exports map ↔ tsdown entries 1:1; `sideEffects: false` safe.
- **Tests/docs at large:** zero snapshots, no clock/RNG mocking (injected seams only); frozen-oracle vectors asserted with `toEqual`; #910/#912/#913/#916 all carry real regression tests; the five ORM pages, four HTTP verify sections, cli.md, errors.md, and README API surface all match shipped signatures — the drift that remains is enumerated in findings 5, 7, 11, 12.
