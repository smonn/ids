### Alias short-circuit guard (1 survivor, verdict: KILLED)

```ts
src/codecs/timestamp/index.ts:79
- const aliasTestPattern = /[ilo]/;
+ const aliasTestPattern = /[^ilo]/;
```

The negated pattern makes the guard fire defensively on every input that contains any non-i/l/o char. The mutant **diverges** only on input consisting entirely of i/l/o chars — original normalises to `0`/`1`, mutant returns the raw string and `base32Pattern.test` rejects it as invalid.

Killed by `safeParse() canonicalises an all-alias base32 portion` in `src/codecs/timestamp/index.test.ts`.

### C. Encode tail-emit shift (1 survivor, verdict: KILLED)

```ts
src/base32.ts:47
- codes[chi] = valueToCharCode[(value << (5 - bits)) & 0x1f]!;
+ codes[chi] = valueToCharCode[(value << (5 + bits)) & 0x1f]!;
```

The tail emit fires once at the end of `encodeBase32` with `bits` in [0, 4]. For a 16-byte input, `bits = 3`. The original emits the low 3 bits of `value` placed at result positions 2-4; the mutant shifts further left and the low 3 bits get masked away, always yielding 0. Diverges iff the last 3 bits of the input bitstream (= low 3 bits of byte 15) are non-zero.

Killed by `non-symmetric known-answer encoding` in `src/codecs/timestamp/index.test.ts`, which uses `rng: target => { target[9] = 0xff; }` so byte 15 has non-zero low bits.

### D. Encode/decode bit-stream timing (3 survivors, verdict: EQUIVALENT)

| Lines | Mutation                                                         |
| ----- | ---------------------------------------------------------------- |
| 42    | `bits >= 5` → `bits > 5` — defers an emit in encode              |
| 57    | `i < str.length` → `i <= str.length` — extra iteration in decode |
| 61    | `bits >= 8` → `bits > 8` — defers a byte-write in decode         |

All three are byte-for-byte equivalent to the original on **any** input. Line 42 defers an emit when `bits` is exactly 5, but the next iteration's emit extracts the same 5-bit chunk from a higher position in `value` (shifted up by 8 from the new byte load) — same output, just emitted one iteration later. Line 57's extra iteration reads `charCodeToValue[NaN]` which JS coerces to `0`; the value-shift adds zero bits, and the subsequent write would go to a now-out-of-bounds `Uint8Array` index, which is silently ignored. Line 61 follows the same pattern as 42 in the decoder.

These were originally flagged as `KILL` in the v1 audit. The TDD pass added a non-symmetric KAT for both encode and decode (`non-symmetric known-answer encoding` and `non-symmetric known-answer decoding`); none of these mutants died, which prompted the trace. Reclassifying as equivalent rather than test gaps.

Equivalent mutants are an unavoidable feature of mutation testing on bit-stream code. No action.
