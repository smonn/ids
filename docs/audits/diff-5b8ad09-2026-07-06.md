## Open findings (ranked, grouped as filing units)

1. **High (bench-integrity) — the baseline cache warmer makes cross-runner p50 comparison the default path, invalidating the threshold rationale.** `bench/compare.ts:21-26` justifies the ±15%/+30% thresholds with "run-to-run p50 drift <1% on shared CI runners" — a same-runner, paired-measurement claim. #1045's push-triggered warmer (`bench.yml:161-187`) pre-populates `bench-base-<sha>` from a different VM, and GitHub's ubuntu-latest fleet is CPU-heterogeneous (ns-scale sync p50 can differ 10-30% across processor models), so virtually every PR now compares against numbers benched on other hardware: a real +25% sync regression can pass as noise, and a clean PR can page a 🛑 severe. The workflow comment calls the cache "harmless", stating only the wall-clock win. **Direction:** genuine trade-off — record CPU model (`os.cpus()[0].model`) in the report and discard mismatched baselines (fall back to same-runner benching), always re-bench base on-runner (loses part of the 10→2 min win), widen thresholds on the cache-hit path, or accept-and-document. Touches `.github/workflows/bench.yml` → human route regardless. **Disposition: file (maintainer decision, presents the trade-off without prescribing).**

2. **Medium (bench) — compare.ts signal polish: async warn noise above the fold, unvalidated cached JSON, and headline counts that omit new/removed.** (a) `compare.ts:28-36`: the code's own comment says async-crypto p50 swings ±40% on zero code change, yet the ±15% warn threshold still classifies async rows and #1045's restructure promotes warn rows into the headline attention table — steady-state comments will routinely lead with spurious "⚠️ regressions (warn)". Decided direction: async (non-blocking-eligible) benches get their own warn band matching the documented noise (±40%); below it they fold into the collapsed within-noise section. (b) `readReport` (compare.ts:53-62) casts cached JSON without checking `schema`; a stale/drifted cache yields `NaN` deltas that classify `ok` silently — validate and treat mismatch as no-baseline. (c) Headline counts omit new/removed benches, producing "✅ 0 within noise" above an unexplained attention table. Chained after finding 1 (same file). **Disposition: file (ready-agent, blocked by finding 1's issue).**

3. **Medium (test-infra) — the depcruise module-coverage meta-test is vacuous, and the nested-adapters broadening has no fixture.** (a) `src/depcruise-rules.test.ts:293-317` builds `fromPatterns` from every rule's `from.path` — including the broad `^src.*\.ts$` patterns of the three leaf-restriction rules (and it ignores `from.pathNot`) — so every production file always matches and `uncovered` is unreachable; verified with a synthetic `src/totally-new-uncovered-module.ts`, which "passes" coverage while having no dedicated rule. The prior issue's acceptance ("delete any rule → test names the newly uncovered files") is unmet; found independently by two reviewers. Direction: exclude the broad structural/leaf-restriction rules from the pattern set (explicit named skip-list beside the existing `STRUCTURAL_RULE_SKIP_LIST`), and assert a synthetic uncovered path actually fails. (b) #1016 broadened `adapters-no-internals` from `[^/]+` to `.+` for nested subfolders, but `test/fixtures/depcruise/adapters/` has only flat files — a silent re-narrowing passes all tests; add one nested violating fixture + case entry. Same file set. **Disposition: file (ready-agent).**

4. **Medium (test-infra) — docs-snippet-imports guard: `tsx` fences silently skipped, and `export * as ns` re-exports unrecognized.** (a) The fence regex (`test/docs-snippet-imports.test.ts:82`) matches only `ts|typescript|js`; `website/src/content/docs/validation/integrations.md:123` is a live ```tsx snippet importing from `@smonn/ids`that is checked by neither the specifier nor the export validation today — the exact bug class the guard exists for would pass in that block. Extend to`tsx|jsx|javascript`(class-level: any fence language whose content the parser can already handle). (b)`collectSourceExports`' `starRe`/`blockRe`don't recognize`export \* as ns from ...`; unexploited in src/ today but a hole in the #1033 recursion's claimed generality. Out of scope (rejected): rewriting the parser on the TypeScript compiler API — the live gaps are markdown-fence-level, where an AST doesn't help; the regex machinery gained direct unit tests in #1031 and a rewrite is churn without closing the actual failure class. **Disposition: file (ready-agent).**

5. **Medium (test-infra) — the invisible-byte detector has zero direct unit coverage.** The +77 lines #1020's wave added to `test/source-hygiene.test.ts` all exercise `checkCliIdiomLeaks`; `checkContent`/`lintFiles` — the actual raw-NUL/bidi/format-byte rejection logic from the sanitize.ts incident — are covered only by the end-to-end smoke that runs the script over the (clean) live repo and asserts "clean". A regression that silently narrows `FORBIDDEN_RE` keeps the suite green as long as the tree stays clean — the same guard-weakening class the detector exists to stop. Add direct unit tests feeding U+200B/U+FEFF/U+202E/NUL etc. through `checkContent`, mirroring the `checkCliIdiomLeaks` test structure. **Disposition: file (ready-agent).**

9. **Low (docs) — the 1.2.4 empty-hex error-code migration is undocumented.** #1020's decode-then-catch unification deliberately (test-pinned) reclassified empty-string hex keys from `invalid_key_encoding` to `invalid_key_length` (`decodeHex("")` no longer throws; control falls to the length assert).
